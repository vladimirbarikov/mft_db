<ol type="1">

<li>mft_db - это бэкенд для веб-приложения, которое предоставляет пользователям возможность находить следующую информацию:
    <ol type="1">
        <li>Номер и название автокомпонентов (далее 'деталей');</li>
        <li>Номер, размеры и вместимость упаковки;</li>
        <li>Модель автомобиля, в которую устанавливается деталь;</li>
        <li>Производственные линию и цех, где деталь устанавливается в автомобиль;</li>
        <li>Название и адрес поставщика, который производит деталь;</li>
        <li>Статус локализации, производится ли деталь локально или за рубежем;</li>
        <li>Историю изменений номера детали, производственной линии, поставщика и статуса локализации при техическом изменении детали (breakpoint);</li>
    </ol>
</li>

<li>Основной функционал.
    
<ol type="1">
    <li>Пользователи могут просмотривать, вводить, корректировать следующие данные:

**Детали и вес**

| №   | Поле             | Описание                           |
| --- | ---------------- | ---------------------------------- |
| 1   | PART_NUMBER      | Уникальный номер детали            |
| 2   | PART_NAME        | Название детали                    |
| 3   | PART_WEIGHT_KG   | Вес детали в киллограммах          |
| 4   | PART_per_VEHICLE | Количество деталей на 1 автомобиль |

**Модели и производство**
| №   | Поле          | Описание                              |
| --- | ------------- | ------------------------------------- |
| 5   | CONFIGURATION | Конфигурация автомобиля               |
| 6   | MODEL_CODE    | Код модели ('A01', 'A08', 'B02'...)   |
| 7   | MODEL_NAME    | Модель ('Jolion', 'H3', 'F7'...)      |
| 8   | LINE_CODE     | Уникальный код производственной линии |
| 9   | LINE_NAME     | Производственная линия                |
| 10  | WORKSHOP_NAME | Цех ('Assembly', 'Component'...)      |
| 11  | WORKSHOP_CODE | Код цеха ('AS', 'COMP'...)            |

## Упаковка (ящики)
| №     | Поле         | Описание                             |
| ----- | ------------ | ------------------------------------ |
| 12    | PART_per_BOX | Количество деталей в 1 ящике         |
| 13    | BOX_NUMBER   | Уникальный номер ящика               |
| 14    | BOX_TYPE     | Тип ('returnable', 'non-returnable') |
| 15-21 | BOX_*        | Размеры, вес, объем, stacking ящиков |

## Поддоны
| №     | Поле           | Описание                               |
| ----- | -------------- | -------------------------------------- |
| 22    | BOX_per_PALLET | Количество ящиков на поддоне           |
| 23    | PALLET_NUMBER  | Уникальный номер поддона               |
| 24    | PALLET_TYPE    | Тип ('returnable', 'non-returnable')   |
| 25-31 | PALLET_*       | Размеры, вес, объем, stacking поддонов |

## Поставщики
| №   | Поле          | Описание                  |
| --- | ------------- | ------------------------- |
| 32  | SUPPLIER_NAME | Название поставщика       |
| 33  | LOCATION      | Страна                    |
| 34  | CITY          | Город                     |
| 35  | STREET        | Улица                     |
| 36  | BUILDING      | Здание                    |
| 37  | LOCALIZATION  | Локализация ('yes', 'no') |

## Технические изменения (breakpoint)
| №   | Поле                        | Описание                     |
| --- | --------------------------- | ---------------------------- |
| 38  | BREAKPOINT_NUMBER           | Номер технического изменения |
| 39  | BREAKPOINT_DATE             | Дата вступления в силу       |
| 40  | PART_NUMBER_BEFORE_CHANGE   | Номер детали до изменения    |
| 41  | SUPPLIER_NAME_BEFORE_CHANGE | Поставщик до изменения       |
| 42  | LOCALIZATION_BEFORE_CHANGE  | Локализация до изменения     |
| 43  | LINE_NAME_BEFORE_CHANGE     | Линия до изменения           |

</li>



<li>Просмотр основных данных о деталях. Пользователи могут просматривать основные данные о деталях проставив фильтры:


| Фильтр               | Поле фильтрации           | Результат                                   |
| -------------------- | ------------------------- | ------------------------------------------- |
| **По номеру детали** | PART_NUMBER               | Данные **об этой детали**                   |
| **По коду модели**   | MODEL_CODE                | Все детали **для этой модели** + данные     |
| **По модели**        | MODEL_NAME                | Все детали **для этой модели** + данные     |
| **По коду линии**    | LINE_CODE                 | Все детали **с этой линии** + данные        |
| **По линии**         | LINE_NAME                 | Все детали **с этой линии** + данные        |
| **По поставщику**    | SUPPLIER_NAME             | Все детали **от этого поставщика** + данные |
| **По стране**        | LOCATION                  | Поставщики из страны → их детали + данные   |
| **По городу**        | CITY                      | Поставщики из города → их детали + данные   |
| **По локализации**   | LOCALIZATION ('yes'/'no') | Поставщики по статусу → их детали + данные  |


</li>


<li>Ввод новых данных о деталях. Пользователи могут вводить данные следующими способами:

<ol type="1">
    <li>Новые данные вводятся отдельно для каждого нового номера детали по каждому из вышеперечисленных пунктов;</li>
    <li>Новые данные вводятся массово для большого количества новых номеров деталей с помощью загружаемого файла sample_mft_data.xlsx;</li>
</ol>

</li>


<li>Корректировка имеющихся данных о деталях. Пользователи могут корректировать данные для имеющихся деталей следующим способом:

<ol type="1">
    <li>Данные корректируются отдельно для каждого имеющегося номера детали по каждому из вышеперечисленных пунктов. Номер детали при этом не меняется;</li>
</ol>

</li>

</ol>

</li>




<li>Дополнительный функционал.
        
<b>Пользователи могут вносить и сохранять историю технических изменений номеров деталей, производственных линий, поставщиков и статуса локализации (breakpoint):</b>

<ol type="1">
    <li>Изменение номера детали и производственной линии вводится отдельно для каждого нового номера детали, сохраняя текущий номер детали, код и название производственной линии, название текущего и нового поставщиков и статуса локализации;</li>
    <li>Новые данные вводятся массово для большого количества новых номеров деталей с помощью загружаемого файла sample_breakpoint_data.xlsx;</li>
